# terraform-modules

Shared Terraform modules for my AWS setup, used by
[AWS](https://github.com/oskarrn93/AWS) and [Pappa-hemsidor](https://github.com/oskarrn93/Pappa-hemsidor).

| Module | Contents |
| --- | --- |
| [`static-website`](static-website) | Several static sites in one private S3 bucket behind one CloudFront distribution, with a shared ACM certificate, Route 53 aliases, `www.` → apex redirect, optional `preview.` hosts (never indexed), security headers and optional uptime monitoring |
| [`website-monitoring`](website-monitoring) | Route 53 HTTPS health check + CloudWatch alarm for one domain, emailing through SNS when it goes down and when it recovers |

## Usage

Reference a module by git source, pinned to one of its tags:

```hcl
module "static_website" {
  source = "git::https://github.com/oskarrn93/terraform-modules.git//static-website?ref=static-website/v1.0.0"

  providers = {
    aws           = aws
    aws.us_east_1 = aws.us_east_1 # certificate and health checks live in us-east-1
  }

  name = "example"

  sites = {
    "example.com" = {
      zone_id      = aws_route53_zone.example.zone_id
      content_path = "${path.root}/site" # optional: uploaded to example.com/ in the bucket
      preview      = true                # also serve preview.example.com
    }
  }

  monitoring = {
    emails = ["me@example.com"]
  }
}
```

```hcl
module "website_monitoring" {
  source = "git::https://github.com/oskarrn93/terraform-modules.git//website-monitoring?ref=website-monitoring/v1.0.0"

  providers = {
    aws = aws.us_east_1 # Route 53 health check metrics only exist in us-east-1
  }

  domain_name = "example.com"
  emails      = ["me@example.com"]
}
```

The shared certificate covers each site's apex and wildcard. ACM allows 10 names per certificate by
default, so more than 5 sites in one `static-website` instance needs a quota increase.

While changing a module, point the consumer at a local checkout instead of the tag, e.g.
`source = "../terraform-modules/static-website"`, and switch back once the new version is tagged.

## Versioning

Each module is versioned on its own with [SemVer](https://semver.org) tags named `<module>/vX.Y.Z`:

- **Major**: consumers must change their code, or resources get replaced (renamed resource
  addresses, removed variables, new required variables).
- **Minor**: new optional variables or outputs, new behaviour that's off by default.
- **Patch**: fixes that don't change the interface.

Tags are created by the [Release workflow](#releasing), not by hand.

Modules set only minimum Terraform and provider versions; consumers pin the exact ones.

## Development

Needs [Terraform](https://developer.hashicorp.com/terraform/install) (version in
[`.terraform-version`](.terraform-version)), [TFLint](https://github.com/terraform-linters/tflint),
[terraform-docs](https://terraform-docs.io) and [pre-commit](https://pre-commit.com). Once per clone:

```sh
pre-commit install # terraform fmt, terraform-docs, tflint and whitespace/line-ending fixes on every commit
tflint --init
```

A hook that reformats files fails the commit; review the changes, `git add` and commit again.

Checks, the same ones CI runs on every pull request (and fails on):

```sh
pre-commit run --all-files                                # format, docs, lint
for d in */examples/*/; do terraform -chdir="$d" init -backend=false && terraform -chdir="$d" validate; done
for m in static-website website-monitoring; do terraform -chdir="$m" init -backend=false && terraform -chdir="$m" test; done
```

- **Format:** `terraform fmt -recursive`; CI fails if it changes any file.
- **Docs:** each module's README has hand-written sections on top and Requirements, Providers,
  Resources, Inputs and Outputs tables generated by terraform-docs (config in
  [`.terraform-docs.yml`](.terraform-docs.yml)) between the `BEGIN_TF_DOCS`/`END_TF_DOCS` markers.
  CI fails if they're out of date.
- **Lint:** TFLint with the shared [`.tflint.hcl`](.tflint.hcl): every Terraform language rule
  (`preset = "all"`) plus the AWS ruleset.
- **Validate:** through each module's `examples/`, root configurations that also show how to call it.
  (`static-website` needs an aliased provider, so it can't be validated on its own.)
- **Test:** `terraform test` against mocked providers, so no AWS credentials are needed.

## Releasing

Actions → **Release** → Run workflow, then pick the module and the bump. It runs CI on `main`, works
out the next `<module>/vX.Y.Z` from the module's latest tag (first release: v1.0.0), and creates the
tag and a GitHub release listing the commits that touched the module since its previous release.
It refuses to release a module with no changes.
